# Переезд на VPS: mashuk.online

Чек-лист переноса портала с Tilda на собственный сервер.
Детали установки — в [ДЕПЛОЙ.md](ДЕПЛОЙ.md).

## 1. Подготовка сервера

- VPS Timeweb, Ubuntu 24.04, 2 vCPU / 4 ГБ (+ swap 2 ГБ), Docker и Compose.
- DNS: A-записи `mashuk.online` и `www.mashuk.online` → IP сервера.
- Порты 80 и 443 открыты (Caddy получит TLS автоматически).

## 2. Переменные

```bash
scp deploy/.env.production.example .env
nano .env   # DOMAIN=mashuk.online, ACME_EMAIL, POSTGRES_PASSWORD, AUTH_SECRET, GF_...
```

## 3. Запуск и миграции схемы

```bash
docker compose --env-file .env up -d
docker compose --env-file .env --profile tools run --rm tools pnpm db:migrate
docker compose --env-file .env --profile tools run --rm tools pnpm admin:create -- admin@czmashuk.ru "Имя"
```

## 4. Перенос заявок из старой базы форм

Старые файлы (согласия, портфолио, сканы) положить на сервер рядом, например
`/opt/mashuk/legacy-uploads`.

```bash
cd /opt/mashuk
docker compose --env-file .env --profile tools run --rm \
  -e LEGACY_DATABASE_URL=postgres://…старая база… \
  -e LEGACY_UPLOAD_DIR=/legacy-uploads \
  -v /opt/mashuk/legacy-uploads:/legacy-uploads:ro \
  tools pnpm migrate:legacy --uploads=/legacy-uploads
```

Сначала полезно прогнать `--dry-run`. Повторный запуск безопасен: уже
перенесённые заявки (по `payload_raw._legacy_id`) пропускаются.

## 5. Приёмка на поддомене (до переключения DNS)

- Развернуть и проверить по временному адресу/`sslip.io`:
  `/`, `/apply`, `/info`, `/muni`, `/events/seminar`, `/events/media`,
  `/results/education-height`, `/admin`, `/admin/applications`.
- Проверить вход в админку, выгрузки Excel и ZIP, скачивание файлов заявок.

## 6. Переключение

- Перевести DNS `mashuk.online` и `www` на новый сервер (Caddy сделает TLS).
- В Tilda настроить редиректы на новый сайт (301):
  - главная → `https://mashuk.online/`
  - страницы лендингов → соответствующие новые URL (`/events/…`, `/results/…`)
  - страницы с формами → `/apply`, `/info`, `/muni`
- Внешние системы оставить как есть: `lms.mashuk.online` (курсы),
  `центрзнаниймашук.рф`, `mashuk.online/bestpractice` — ссылки с портала ведут на них.

## 7. После переключения

- Бэкапы: cron `deploy/backup.sh` (см. ДЕПЛОЙ.md).
- Мониторинг: `--profile metrics` (Prometheus/Grafana).
- Ошибки: GlitchTip (`deploy/glitchtip`) — при необходимости.
- Убедиться, что `storage/` (файлы заявок и сборки) на постоянном хранилище,
  переживающем обновления образа.
- Через несколько недель отключить сайт на Tilda.

## 8. Единый вход (SSO) с LMS

Портал выступает OAuth 2.0 / OpenID Connect провайдером, LMS — клиентом.
В LMS: «API и интеграции» → «Настройка OAuth 2.0 / OpenID Connect для Single Sign-On».

Заполнить (значения — из `.env` сервера):

| Поле в LMS | Значение |
| --- | --- |
| Хост сервера авторизации | `https://mashuk.online` |
| Uid oAuth id | `OAUTH_CLIENT_ID` (например, `mashuk-lms`) |
| Секретный ключ | `OAUTH_CLIENT_SECRET` |
| Скоупы oAuth2 | `openid email profile phone` |
| Авторизованный url | `https://mashuk.online/api/oauth/authorize` |
| Токен url | `https://mashuk.online/api/oauth/token` |
| Url эндпоинта информации о пользователе | `https://mashuk.online/api/oauth/userinfo` |
| Ключ для email | `email` |
| Ключ для имени | `given_name` |
| Ключ для фамилии | `family_name` |
| Ключ для телефона | `phone_number` |
| Ключ для uid провайдера | `sub` |

Включить «OpenID Connect». На странице входа LMS — «Показывать кнопку входа
при помощи SSO».

Проверка: `https://mashuk.online/.well-known/openid-configuration` отдаёт адреса;
вход начинается с `/api/oauth/authorize` и требует активной сессии портала.

Секреты (можно сгенерировать): `OAUTH_CLIENT_SECRET` — `openssl rand -base64 32`.
