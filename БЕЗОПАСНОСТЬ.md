# Безопасность и соответствие законодательству РФ

Документ фиксирует меры, реализованные в портале `mashuk.online`, и
организационные действия, которые нужно выполнить вне кода.

## 1. Персональные данные (152-ФЗ)

- **Правовая основа и согласия.** Во всех формах (семинар, данные участников,
  муниципалитеты, медиа) есть обязательные согласия на обработку ПДн; для
  семинара и муниципалитетов — подписанный документ (Word/PDF) с загрузкой скана.
- **Политика конфиденциальности** — отдельная страница `/privacy` с реквизитами
  оператора, целями, составом данных, правами субъекта и контактами. Ссылки на
  неё есть в подвале и в каждой форме.
- **Локализация баз данных.** Сервер и PostgreSQL находятся в РФ (Timeweb,
  Москва). Файлы (согласия, портфолио, сканы) хранятся на том же сервере
  (или в S3-совместимом хранилище в РФ). Трансграничной передачи нет.
- **Cookie и аналитика.** Аналитика (Яндекс.Метрика) загружается **только после
  явного согласия** пользователя в баннере; выбор запоминается. До согласия
  сторонние счётчики не подключаются.
- **Внешние ресурсы.** Шрифты (Geologica, Noto Serif) подключены локально
  (без Google Fonts), обложки курсов — локальные файлы (без Tilda CDN).
  Единственный внешний сервис — Яндекс.Метрика (РФ) и LMS `lms.mashuk.online`.
- **Минимизация.** Сбор ограничен целями участия в мероприятиях; «лишние» поля
  помечены как необязательные.

### Требуется организационно (вне кода)
- Уведомление Роскомнадзора об обработке ПДн (если ещё не подано).
- Назначение ответственного за обработку ПДн, оценка вреда субъектам.
- Утверждение сроков хранения и порядка уничтожения ПДн.
- Модель угроз и регулярная проверка мер защиты.

## 2. Доступ и аутентификация

- Сессии — непрозрачный токен в `httpOnly` cookie (`SameSite=Lax`, `Secure` на
  HTTPS). Личные пароли и пароли программ — scrypt-хеши.
- Разграничение ролей: участник / модератор / администратор; администратор
  Центра управляет всеми программами.
- **Файлы заявок** (портфолио, согласия, **сканы паспортов**) доступны только
  авторизованному администратору; публичных ссылок нет. Скачивание — через
  проверяемый маршрут, имена файлов обезличены.
- `/uploads/*` (фото из чатов) отдаются только вошедшим пользователям.
- Ограничение попыток входа (лимиты по IP и логину).

## 3. Технические меры

- **HTTPS/HSTS**, HTTP/2/3; заголовки `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Content-Security-Policy`.
- **Антиспам форм:** лимит 12 отправок/10 мин на IP + скрытая ловушка (honeypot).
- **Валидация на сервере:** обязательные поля, форматы e-mail, СНИЛС/ИНН,
  проверка региона; серверная проверка длины ответов.
- **Файлы:** проверка сигнатур (PDF/JPG/PNG/DOC/DOCX) и размера (до 20 МБ),
  хранение под случайными именами.
- **SQL:** параметризованные запросы; динамические имена таблиц/колонок берутся
  только из фиксированных списков.
- **XSS:** контент рендерится React (без `dangerouslySetInnerHTML`), редактор
  хранит документы TipTap JSON.
- **Секреты** — только в переменных окружения на сервере, в git не попадают
  (`.env*` в `.gitignore`).

## 4. Зависимости

`pnpm audit --production`: 1 moderate — `uuid` (<11.1.1) транзитивно через
`exceljs`. Уязвимость касается v3/v5/v6 с переданным `buf`; `exceljs`
использует v4 для генерации идентификаторов, поэтому практический риск низкий.
Обновление форсированием мажорной версии может сломать экспорт Excel — оставлено
на контролируемый апдейт.

## 5. Реагирование и эксплуатация

- **Бэкапы** БД и файлов ежедневно (cron), хранение 7 дней.
- **Автообновление** образа из `ghcr.io` и конфигурации из `main` (cron).
- **Файрвол** (ufw): открыты только 22/80/443.
- Рекомендуется: выгрузка бэкапов во внешнее хранилище (rclone/S3), смена
  root-пароля сервера, доступ по SSH-ключам, мониторинг ошибок (GlitchTip).

## 6. Важное действие по секретам

Секрет OAuth-клиента LMS ранее попал в историю git (файл документации).
Из актуальных файлов он удалён. **Рекомендуется перевыпустить секретный ключ
приложения `mashuk-online` в панели LMS** и обновить `LMS_OAUTH_CLIENT_SECRET`
в `.env` на сервере.
